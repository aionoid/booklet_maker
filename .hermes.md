# Agent Instructions: Booklet Maker (`bookit.sh`)

You are an expert developer assistant specialized in shell scripting (Bash), command-line utility design, Go CLI integration (`pdfcpu`), NixOS environment management, Test-Driven Development (TDD) for shell scripts using `bats`, document imposition, and Git workflows. Follow these strict core guidelines for all interactions on this project.

## 1. Project & System Context

- **Purpose:** A PDF imposition tool that takes an input PDF and arranges/imposes its pages for printing as a book, supporting flexible layouts of **1 page (1p), 2 pages (2p), 4 pages (4p), or 8 pages (8p) per A4 sheet**. Two implementations share the same pipeline:
  - **Shell:** `bookit.sh` + `helper.sh` — the original Bash CLI.
  - **Go:** `go_app/` — a pure Go CLI + Fyne GUI built on pdfcpu's **Go API** (`github.com/pdfcpu/pdfcpu/pkg/api`) directly (no shelling out to the `pdfcpu` binary). This is the primary, actively-developed implementation.
- **Core Architecture:**
  - `bookit.sh`: Main CLI entry point handling argument parsing, workflow orchestration, and user feedback (shell version).
  - `helper.sh`: Modular library containing mathematical imposition/signature calculations, page-padding logic, rotation rules, and `pdfcpu` wrapper functions.
  - `go_app/`: Go implementation — `main.go` (entry point, CLI vs GUI), `booklet.go` (full pipeline: pad blanks → reverse RTL → booklet → stamp stations/folios → split → n-up front/back), `cli.go` (argument parsing), `gui.go` (Fyne GUI), `Makefile` (build/test targets).
- **Core Engine:** Relies on **`pdfcpu`** (written in Go) as the underlying PDF manipulation engine.
- **Target Environment:** **NixOS Linux host**. All commands, paths, shebangs (e.g., `#!/usr/bin/env bash`), and environment setups must conform to NixOS standards (e.g., using `nix-shell`, `flake.nix`, or `shell.nix` for reproducible dependencies like `pdfcpu`, `bats`, and coreutils).
- **Layout & Imposition Rules:** Must accurately calculate signatures, page padding (blank pages to fill signature multiples), page rotations, scaling, and grid arrangements for A4 output sheets across 2p, 4p, 6p, and 8p imposition configurations.

## 2. Test-Driven Development (TDD) Principle

- **Red-Green-Refactor Cycle:** Strictly enforce TDD for all script enhancements, argument validation, imposition math functions in `helper.sh`, and wrapper features in `bookit.sh`:
  1. **Red:** Write a failing test using **`bats` (Bash Automated Testing System)** defining the expected CLI behavior, imposition page order array, error code, or output PDF properties before writing any script code.
  2. **Green:** Write the minimal amount of shell script logic in `helper.sh` or `bookit.sh` required to make the test pass successfully.
  3. **Refactor:** Clean up code, ensure clean separation of concerns between `bookit.sh` and `helper.sh`, and optimize error handling while keeping tests green.
- **Test Coverage:** Maintain comprehensive test suites covering unit tests for `helper.sh` math/ordering functions and integration tests for `bookit.sh` (e.g., odd page counts, missing `pdfcpu` dependencies, invalid layout parameters, and malformed input PDFs).

## 6. Deployment & Local Testing on NixOS

When preparing a release or testing the CLI tool locally on NixOS, follow these exact steps:

### A. NixOS Environment & Dependencies
1. Ensure required packages (`pdfcpu`, `bats`, `bash`, `coreutils`) are available via system configuration, `nix-shell`, or Nix Flakes (`nix develop`):
   ```bash
   nix-shell -p pdfcpu bats
   ```
2. Verify tool versions:
   ```bash
   pdfcpu version
   bats --version
   ```

### B. Running Tests
1. Ensure scripts have executable permissions (`chmod +x bookit.sh helper.sh`) and execute the test suite:
   ```bash
   bats tests/
   ```

### C. Manual Smoke Testing
1. Run `bookit.sh` against a sample PDF for each supported layout (`2p`, `4p`, `6p`, `8p`):
   ```bash
   ./bookit.sh -l 4p input.pdf output_booklet.pdf
   ```
2. Inspect output metadata, page dimensions (A4), and page count:
   ```bash
   pdfcpu info output_booklet.pdf
   ```

### D. Go application (primary)
The Go app lives in `go_app/`. It needs the shell deps plus X11 libraries for the Fyne GUI (`libx11`, `libxxf86vm`).

1. **Build** (from repo root; `shell.nix` already lists all deps):
   ```bash
   nix-shell --command "cd go_app && make build"
   # -> go_app/bin/booklet-maker
   ```
   Or directly:
   ```bash
   nix-shell -p go pkg-config cairo glib gtk3 libx11 libxxf86vm --command \
     "cd go_app && go build -o bin/booklet-maker ."
   ```
2. **Run CLI** (same 6 options as `bookit.sh`):
   ```bash
   ./go_app/bin/booklet-maker -input input.pdf -output my_booklet.pdf -pages 4 -direction LTR
   # -i input, -o output (default booklet.pdf), -p pages (1/2/4/8),
   # -d direction (RTL/LTR), -s sections (8), -b blank (0/1)
   # Outputs: my_booklet.pdf, sections/*.pdf, print_ready/*_F.pdf & *_B.pdf
   ```
3. **Run GUI** (requires an X display):
   ```bash
   ./go_app/bin/booklet-maker -gui
   ```
4. **Test:**
   ```bash
   nix-shell -p go --command "cd go_app && go test ./..."
   ```
